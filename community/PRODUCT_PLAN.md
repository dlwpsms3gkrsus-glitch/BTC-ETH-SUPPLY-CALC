# CryptoFlow 제품 기획: 승인 준비 먼저, 재방문 다음

## 1. 목표와 이번 PR의 역할

**첫 번째 목표는 Google AdSense 승인을 받을 수 있도록 사이트의 콘텐츠와 운영 준비를 강화하는 것**, 두 번째는 이용자가 꾸준히 돌아오는 플랫폼을 만드는 것이다. Google의 개별 심사 결과나 승인 시점을 보장할 수 없으며, 글 수·글자 수·방문자 수의 임의 기준을 공식 승인 조건처럼 제시하지 않는다.

이번 PR은 기존 BTC/ETH 계산기와 연결되는 커뮤니티의 설계·브라우저 데모·예제 이미지 생성 스크립트를 제공한다. 실제 회원 서비스, 운영자 인증, 공유 게시판, 광고 신청·설정·배포는 하지 않는다. 데모 화면의 글·댓글 수는 샘플이며 실제 이용 실적이나 최신 시장 동향이 아니다. `noindex,nofollow`로 검색 노출을 의도하지 않으며 광고와 분석 스크립트도 없다.

## 2. 공식 자료에서 가져온 원칙

- [독창적이고 관련성 있는 콘텐츠](https://support.google.com/adsense/answer/1355699?hl=en): 다른 사이트의 글을 모으는 방식보다 이용자에게 고유한 가치를 제공하는 자체 콘텐츠를 우선한다.
- [사용자 생성 콘텐츠에 대한 게시자의 책임](https://support.google.com/adsense/answer/7299563?hl=en): 회원이 작성한 내용이라도 광고가 게재되는 페이지의 정책 준수 책임은 사이트 운영자에게 있다.
- [UGC 관리 권장 사항](https://support.google.com/adsense/answer/3011869): 검토 전 광고 비활성화, 신규 이용자의 기여 검토, 링크·이미지 제한, 신고 도구 등을 운영 설계에 반영한다.

이 자료들은 준비 방향의 근거이지 모든 심사 요건을 대체하는 체크리스트가 아니다. 신청 시점에 최신 AdSense 자격·프로그램 정책과 Google 게시자 정책을 다시 확인한다. `noindex` 설정이나 신고 버튼만으로 정책 준수나 승인을 확보할 수는 없다.

## 3. 승인 준비에 먼저 투자할 콘텐츠

계산기 자체의 목적과 사용법을 명확히 하고, 계산 결과를 이해하는 데 필요한 원본 설명 시리즈를 만든다. 아래는 **작성 제안**이며 이번 PR에서 완성·게시됐다는 뜻이 아니다.

1. **BTC 공급량 읽기**: 최대 공급량, 유통량, 발행량의 차이와 데이터 제공자별 정의. 계산기에 실제 사용되는 출처와 단위부터 검증한다.
2. **ETH 공급 변화 읽기**: 발행과 소각의 구분, 관측 기간과 네트워크 조건이 해석에 미치는 영향. 단순 고정 공급 모델의 한계를 설명한다.
3. **계산 결과 검산하기**: 입력값·단위·기준 시각을 명시한 재현 가능한 예제와 반올림·오차 설명. 가상 값은 가상 값으로 표시한다.
4. **시가총액과 공급량 오해 풀기**: 공급 변화만으로 가격을 예측할 수 없는 이유와 계산기의 한계. 수익 보장·매수 권유를 하지 않는다.
5. **데이터 업데이트 기록**: 출처, 관측 시각, 변경 사항, 정정 내역. 검증하지 않은 현재 수치나 '지금 유행'을 만들어 넣지 않는다.

각 글에는 독자의 질문, 직접 작성한 설명, 확인 가능한 원출처, 계산 예제, 한계, 검토일, 관련 계산기·가이드 링크를 포함한다. 핵심 설명은 누구나 접근 가능한 운영 문서로 제공하고, 비어 있는 글·중복 페이지·검색어만 바꾼 양산 콘텐츠는 피한다. 사이트 소개·문의·개인정보 처리방침·콘텐츠 운영 및 정정 정책도 실제 운영 내용에 맞게 작성한다. 형식적인 정책 페이지를 추가하는 것만으로 승인이 보장되지는 않는다.

## 4. 재방문 플랫폼의 정보 구조

디시인사이드 등 게시판에서 참고하는 범위는 **최신/인기/공지와 제목·댓글 중심 목록이라는 정보 구조**다. 특정 커뮤니티의 로고·화면 복제, 회원 글·댓글·이미지·밈의 무단 복사는 하지 않는다. 실제 경쟁 서비스 이용 행태나 인기 순위를 조사·검증했다는 주장도 하지 않는다.

- BTC / ETH / 계산기 질문 / 자유 주제로 진입점을 나눈다.
- 최신 목록은 새 질문을 빠르게 찾게 하고, 인기 목록은 명확한 기준·기간을 적용한다. 운영에서 봇이나 중복 반응을 인기 지표로 계산하지 않는다.
- 공지는 사용 규칙·데이터 변경·정정 사항을 전달한다. 초기 화면의 데모 반응 수를 실제 인기처럼 홍보하지 않는다.
- 게시글과 교육용 가이드, 계산기를 서로 연결해 단순 시세 잡담 이상의 방문 이유를 만든다.
- 밈·트렌드는 설명을 쉽게 만드는 소재로만 사용한다. 실제 관심 증가를 출처와 시점으로 확인한 경우에만 다루고, 직접 만든 이미지나 사용 허락이 있는 자료를 쓴다. 펌프·리딩방·수익 인증 유도·제휴 홍보를 성장 전략으로 삼지 않는다.

## 5. 질문을 원본 가이드로 발전시키는 운영

`반복 질문 확인 → 사실/출처 검증 → 운영자가 독립적인 설명 작성 → 가이드 검토·발행 → 관련 질문에 연결 → 정정 및 갱신`

댓글을 그대로 긁어 모아 검색용 글로 만들지 않는다. 질문의 일반적 주제를 바탕으로 새 설명을 작성하고, 특정 회원의 원문을 인용해야 하면 공개 정책과 인용 권한·개인정보를 확인한다. 답변이 불명확한 주제는 불확실성을 밝히며 가이드 수를 채우기 위해 단정하지 않는다. 초기에 운영 가능한 발행 주기를 정하고 데이터가 바뀌었을 때 먼저 기존 글을 고친다.

## 6. 단계별 진행과 완료 조건

### A. 승인 준비 기반

기존 사이트의 실제 콘텐츠·모바일 사용성·탐색·데이터 출처·오류·정책 페이지를 점검한다. 독창적 설명 시리즈를 검토해 공개하고 빈 페이지와 샘플을 운영 콘텐츠에서 분리한다. 저품질 UGC를 늘리는 대신 계산기와 가이드의 유용성을 먼저 높인다. 구체적인 콘텐츠 수를 승인 보장 기준으로 삼지 않는다.

### B. 안전한 커뮤니티 운영 준비

[ARCHITECTURE.md](ARCHITECTURE.md)의 인증 API·DB·권한·신고·보존 정책을 구축하고 테스트한다. 신규 사용자 검토, 링크/이미지 제한, 숨김·복원·이의 제기 절차와 담당자를 확정한다. 공개 상태와 광고 허용 상태를 분리하고 검토되지 않은 UGC에는 광고를 게재하지 않는다. 게시글뿐 아니라 새 댓글과 수정도 재검토 대상이다. 필요하면 검토된 가이드 중심으로 먼저 운영하고 커뮤니티 광고는 계속 꺼 둔다.

### C. 심사와 재방문 개선

최신 공식 요건 확인과 운영 검토 후 별도 승인받아 신청·배포한다. 심사 결과의 구체적 지적을 수정하고, 승인 전후 모두 정책 준수를 지속한다. 심사 통과만을 목표로 일시적으로 콘텐츠를 숨겼다가 복구하는 방식은 쓰지 않는다.

실제 서비스가 마련된 뒤 개인정보·동의 요건을 검토한 측정 수단으로 재방문율, 질문 응답률, 질문→가이드 이동, 가이드 정정 속도, 신고 처리 시간을 살핀다. 클릭 유도나 광고 클릭·노출 조작을 지표로 삼지 않는다. 현재 데모에는 실제 이용자 추적이 없다.

## 7. 범위와 승인 경계

이번 변경은 `community/` 안에만 둔다. 기존 루트 계산기 변경, main 병합, 운영 배포, 유료 서비스 설정, AdSense 계정 연결·신청은 포함하지 않는다. 향후 비용·외부 서비스·실제 운영 전환은 별도 승인 후 진행한다. 제공하는 스크린샷은 구현 예시이며 실제 서비스 운영·광고 승인·수익 발생의 증거가 아니다.
